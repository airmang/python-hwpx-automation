# 개인정보(PII) 다루기 — workflows-pii

**언제:** 양식 채움·메일머지·추출 경로로 **개인정보(주민등록번호·연락처·이메일·카드·계좌·주소·이름)**가 흐를 때. 사람을 대체해 문서를 처리하는 LLM은 개인정보 보호법상 **탐지+마스킹+최소화** 의무를 진다. 이 문서는 그때 도구가 해 주는 것과 에이전트가 직접 해야 하는 것을 나눠 적는다.

**핵심:** 가림(`mask`)은 **아래 추출 도구 5개의 결과에만** 걸리고 기본으로 켜져 있다. 그 밖의
읽기 도구는 **원문을 그대로** 돌려준다. 쓰기 도구인 폼필·메일머지에는 가림 인자가 없으므로
입력 값을 먼저 최소화·가명화하거나 가린 뒤 전달해야 한다. 가림과 검사는 정해진 표기만
알아본다(아래 "탐지하는 표기").

## 도구가 하는 것

- **가리는 도구 5개** — `get_document_text` · `hwpx_to_markdown` · `hwpx_extract_json` ·
  `document_to_markdown` · `document_extract_json`. `mask=true`가 기본이고, 결과에 실린 글에서
  탐지한 값을 `010-****-****`처럼 바꾼다. 명시적으로 승인된 원문 확인에만 `mask=false`를 쓴다.
  - 가림은 그 도구가 실은 글에만 걸린다. 도구마다 싣는 자리가 다르다(예: `get_document_text`는
    본문과 표 칸만 싣는다).
  - `hwpx_extract_json(format_detail=True)`의 런 글(`format.runs[].text`, 각주의
    `bodySpans[].text`)은 문단 글을 기준으로 가린다. 서식이 달라 런이 나뉜 번호도 가려지고,
    가린 값은 그 값이 시작한 런에 실린다(이어지는 런에서는 그 부분이 빠진다).
- **가리지 않는 읽기 도구 (원문)** — `hwpx_to_html`, `get_paragraph_text` ·
  `get_paragraphs_text` · `get_location_text`, `get_table_text` · `get_table_map` ·
  `find_cell_by_label`, `find_text`, `get_document_outline`, `get_document_map`,
  `get_document_node` · `query_document_nodes`, `dump_document_blueprint`, `doc_diff`,
  `scan_form_guidance` · `list_form_fields`, 고급 도구 `package_get_text` · `package_get_xml` ·
  `object_find_by_tag`. 이 도구들에는 `mask` 인자가 없다. 가려진 글을 받은 뒤 이 도구들을
  부르면, 그 도구가 싣는 자리에 있는 값은 원문으로 온다.
- **쓰기 도구의 응답** — `search_and_replace` · `apply_edits`의 `semanticDiff`(바뀌기 전/후 글)는
  `dry_run`에서도 원문이다. `apply_form_fill`은 받은 값을 그대로 쓰고 응답의 보고만
  가린다(`responseMasked`). `mail_merge`는 값을 그대로 쓴다. 두 도구 모두 가림 인자가 없다:
  정제된 plan 값/`data_rows` 또는 정제된 데이터 파일만 입력하고 결과를 다시 검사한다.
- `scan_personal_info(filename|text)` — 읽기 전용 검사. 유형별 건수(`byType`)와 가린 예시만
  돌려주고 원본값은 돌려주지 않는다. 값을 가리거나 지우지는 않는다.
  - 검사하는 자리(`scanned`): 본문, 표 칸(칸 안 표 포함), 글상자, 캡션, 머리말, 꼬리말, 각주,
    미주, 메모, 바탕쪽, 숨은 설명(이 자리들의 덧말을 단 글·겹쳐 쓴 글자 포함), 누름틀
    안내문·도움말, 양식 개체(입력 상자·콤보 상자의 글, 선택 상자·라디오 단추·명령 단추의
    이름표), 수식, 문서 정보(제목·만든 사람·주제·설명·키워드·마지막 저장한 사람),
    미리 보기 글(`Preview/PrvText.txt`). 변경 추적으로 지운 글도 문단 글에 들어 있어 함께
    검사한다. 자리별 건수는 `byPlace`.
  - 검사하지 않는 자리(`notScanned`): 그림·스캔 이미지 속 글자, 글맵시·차트·OLE 개체
    안의 글, 하이퍼링크 주소와 책갈피·누름틀·셀 필드의 이름·개체 설명, 변경 추적·메모의 작성자
    이름·문서 이력·스크립트. 읽으려다 못 읽은 자리도 까닭과 함께 여기에 실린다.
  - `total: 0`은 "`scanned` 자리에서, 아래 표기로는 찾지 못했다"는 뜻이다. 개인정보가 없다는
    보증이 아니다.

## 탐지하는 표기 (한계)

가림과 `scan_personal_info`는 같은 탐지기를 쓴다.

- **기계세트(high-confidence)** — 아래 표기일 때만 잡는다.
  - 휴대폰: `010`·`011`·`016`~`019`로 시작하고 붙임표(`-`)로 잇거나 붙여 쓴 번호
    (`010-0000-0000`, `01000000000`).
  - 주민등록번호: 앞 6자리 + 1~4로 시작하는 뒤 7자리. 붙임표로 잇거나 붙여 쓴 꼴.
  - 이메일: `이름@도메인` 꼴.
  - 카드: 16자리(4자리씩 붙임표·공백으로 나누거나 붙여 쓴 꼴)이고 검증 숫자(Luhn)가 맞는 번호.
- **못 잡는 표기** — 공백·점·괄호로 나눈 휴대폰 번호, `+82` 표기, 전각 숫자, 붙임표가 아닌
  줄표(`–`), 유선 번호, 외국인등록번호(뒷자리가 5~8로 시작), 공백을 낀 주민등록번호, 점으로 나눈
  카드 번호, 전각 `＠`를 쓴 이메일, 여권·운전면허 번호.
- **맥락형(low-confidence)** — 이름표가 값 바로 앞, 같은 글 안에 있을 때만 잡는다:
  `계좌(번호)`·`통장(번호)` 뒤의 10~14자리 번호, `주소`·`도로명주소`·`소재지`·`거주지` 뒤의
  시·도 이름으로 시작하는 주소, `성명:`·`수신자:`·`이름:`(쌍점 필요) 뒤의 한글 2~4자.
  이름표 없는 값은 건드리지 않는다(과하게 가리지 않으려는 것).
- **표 양식** — 이름표 칸과 값 칸이 나뉘어 있으면 이름은 잡지 못하고, 주소·계좌는 도구가 칸
  글을 어떻게 이어 붙이느냐에 따라 잡히기도 놓치기도 한다. 한글 양식의 이름·주소·계좌가
  가려진다고 가정하지 않는다.

## 루프

1. **검사(선택):** `scan_personal_info` 로 어떤 유형이 어느 자리(`byPlace`)에 몇 건 있는지 먼저
   본다(가린 예시). `notScanned`에 실린 자리는 보지 않은 것이다.
2. **처리:** 글을 읽을 때는 가리는 도구 5개를 기본 `mask=true`로 쓴다. 편집 자리를 찾으려고
   원문 도구(`find_text`·`get_document_map` 등)를 부르면 그 결과에는 원문이 실린다는 것을 알고
   쓴다. 폼필·메일머지는 필요한 값만 남기고 사전에 가리거나 가명화한 입력을 전달한다.
   - 메일머지: 정제된 행 값으로 FitPolicy를 계산하고 원본 PII 데이터 파일을 evidence에 복사하지 않는다.
   - 추출: 반환 텍스트에서 값이 가려졌는지 확인한다(위 표기 밖의 값은 가려지지 않는다).
   - 폼필: 정제된 값만 plan/value에 넣고 응답 echo에도 원문 PII가 없는지 확인한다.
3. **가명/비식별(선택):** 가명=결정적 토큰맵(`이름_001`), 비식별=불가역 salted-hash. 필드 최소화로 불필요한 PII 열 제거.
4. **누출 확인:** 합성 코퍼스 산출물을 raw-PII 패턴/`detect_pii` 로 스캔 → **기계세트 0 hit** 이
   게이트. 같은 탐지기를 쓰므로 탐지기가 놓치는 표기는 이 게이트도 통과한다.

## 안전 수칙 (정직 보고)

- **기계세트는 가리는 도구 5개의 결과에서, 탐지하는 표기일 때 가려진다.** 모든 도구에서 항상
  가려지는 것이 아니다. **맥락형=low-confidence 정직 라벨** — 라벨(`주소:`/`성명:` 등) 있을 때만
  발화, 자유텍스트/순수값엔 미발화(과마스킹 방지). 이름은 라벨-only(수신자 이름을 지우지 않음).
- "누출 0"은 **기계세트의 탐지하는 표기 기준**이며, 맥락형 누락과 탐지 밖 표기는 통과로
  보고하지 않는다.
- 서버에는 로그를 가리는 장치가 걸려 있지 않다. 호스트가 남기는 기록(대화·도구 호출 기록)도
  이 도구의 범위 밖이다.
- 가역 가명처리(외부 KMS)는 v1 범위 밖(honest-defer). v1=비식별 hash + 단순 가명 토큰맵.
